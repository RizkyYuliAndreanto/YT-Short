## 🧠 CLAUDE OPUS-STYLE REASONING FRAMEWORK

### Core Philosophy (Implicit in All Responses)

The following mindset shapes **every** code analysis:

#### 1. **Defensive by Default**

- Assume inputs can be malicious or malformed
- Assume timing can be adversarial (race conditions)
- Assume resources can run out (memory, connections, file handles)
- Assume dependencies can fail (network, database, external services)
- Document assumptions explicitly; never hide them

#### 2. **Error Paths Are First-Class Citizens**

- Happy path is ~10% of the code; error paths are ~90%
- Test error handling as thoroughly as happy paths
- Errors should be informative (include context, not just "failed")
- Recovery should be explicit (retry? fallback? crash gracefully?)

#### 3. **Reasoning is Explicit, Not Implicit**

- Show the thinking; don't skip steps
- Why this design over alternatives? (explicit trade-offs)
- Why this is safe/performant? (explicit justification)
- Why this will scale? (explicit reasoning about limits)

#### 4. **Consistency Over Cleverness**

- Prefer predictable code over clever code
- Prefer explicit over implicit
- Prefer boring patterns over novel approaches
- When you don't understand code at a glance, it's wrong

#### 5. **System-Level Thinking**

- How does this interact with other parts?
- What invariants must hold? Can they be violated?
- What happens at scale? What breaks first?
- How will this be debugged 6 months from now?

## 🛡️ ERROR HANDLING PHILOSOPHY (Claude Opus Style)

This is **how Opus thinks about errors**. Embed these principles in your questions:

### Principle 1: Errors Are Data

```
❌ Don't think: "Error handling is defensive programming overhead"
✅ Think: "Error handling is core business logic"

Example:
❌ Bad: `try { db.query() } catch { return null }`
✅ Good:
  try {
    db.query()
  } catch (ConnectionError e) {
    log.warn("Database unavailable, using cache fallback", e)
    return cachedResult()
  } catch (InvalidQuery e) {
    log.error("Query error indicates code bug", e)
    rethrow(e)  // Let upstream handle code bug
  }
```

### Principle 2: Explicit Error Paths

```
❌ Don't: Hide errors in generic catch-alls
✅ Do: Name each error scenario explicitly

Example:
❌ Bad:
  catch (Exception e) {
    log.error("Failed", e)
    throw new RuntimeException("Error")
  }

✅ Good:
  catch (DatabaseConnection e) { /* handle connection */ }
  catch (DatabaseTimeout e) { /* handle timeout */ }
  catch (InvalidSQL e) { /* handle code bug */ }
  catch (PermissionDenied e) { /* handle auth */ }
```

### Principle 3: Error Context is Critical

```
❌ Don't: `throw new Error("Failed")`
✅ Do: `throw new Error("Failed to process order #12345:
         Customer credit limit $1000 but transaction $1500,
         last successful charge on 2024-01-15")`

Include:
- What operation failed
- What input/ID
- What constraints were violated
- What was the state before failure
- What would success look like
```

### Principle 4: Recovery is Intentional

```
❌ Don't: Guess what to do when things break
✅ Do: Explicitly decide for each error type

For each error, answer:
- Can we retry? (is it transient?)
- Should we retry? (or make it worse?)
- Retry how? (exponential backoff? jitter?)
- How many times? (2? 5? infinite?)
- Fallback to what? (cache? default? fail?)
- Who should handle this? (this layer? upstream?)
- How should this be logged? (DEBUG? WARN? ERROR?)
```

### Principle 5: Temporal Concerns Matter

```
❌ Don't: Ignore when errors happen (startup? runtime? shutdown?)
✅ Do: Handle differently based on context

During STARTUP:
- Fail fast if required dependencies missing
- Don't hide startup errors behind retries

During RUNTIME:
- Transient errors: retry with backoff
- Permanent errors: fail fast
- Partial failures: decide graceful degradation

During SHUTDOWN:
- Finish in-flight requests gracefully
- Give bounded time (don't wait forever)
- Refuse new requests
```

### If Python (Async/Concurrent Focus)

**Opus Pattern for Async Code:**

```python
# ✅ OPUS-STYLE PYTHON ERROR HANDLING

async def process_with_resilience(item_id: int) -> ProcessResult:
    """
    Process item with explicit error handling and recovery strategy.

    Assumptions:
    - item exists (validated by caller)
    - database available within 5s (timeout enforced)
    - external API returns within 10s (timeout enforced)

    Failure modes handled:
    - Database timeout: retry up to 3x with exponential backoff
    - API failure: use cached response, log warning
    - Invalid data: log error, skip item, continue batch
    - Unexpected error: log traceback, fail operation safely
    """

    max_retries = 3
    retry_delay = 0.1

    for attempt in range(max_retries):
        try:
            # Database operation with explicit timeout
            item = await db.fetch_one(
                query="SELECT * FROM items WHERE id = ?",
                params=(item_id,),
                timeout=5.0
            )

            if not item:
                log.error(f"Item not found", extra={"item_id": item_id})
                return ProcessResult(status="NOT_FOUND", reason="item_missing")

            # External API call with fallback
            try:
                api_result = await external_api.enrich(
                    data=item,
                    timeout=10.0
                )
            except TimeoutError as e:
                log.warning(
                    "API timeout, using cached enrichment",
                    extra={"item_id": item_id, "timeout_sec": 10.0}
                )
                api_result = await cache.get(f"enrichment:{item_id}")
                if not api_result:
                    return ProcessResult(
                        status="DEGRADED",
                        reason="api_timeout_no_cache"
                    )
            except ExternalAPIError as e:
                # Permanent API error (not retryable)
                log.error(
                    "API error",
                    extra={"item_id": item_id, "error": str(e)}
                )
                return ProcessResult(
                    status="EXTERNAL_ERROR",
                    reason="api_unavailable"
                )

            # Validate enriched data
            if not _is_valid(api_result):
                log.error(
                    "Invalid enrichment result",
                    extra={"item_id": item_id, "result": api_result}
                )
                return ProcessResult(
                    status="INVALID_DATA",
                    reason="enrichment_invalid"
                )

            # Success path
            saved = await db.save(item_id, api_result)
            log.info(
                "Item processed successfully",
                extra={"item_id": item_id}
            )
            return ProcessResult(status="SUCCESS", data=saved)

        except asyncio.TimeoutError as e:
            # Transient timeout: retry
            if attempt < max_retries - 1:
                log.debug(
                    f"Timeout on attempt {attempt+1}, retrying",
                    extra={"item_id": item_id}
                )
                await asyncio.sleep(retry_delay)
                retry_delay *= 2  # Exponential backoff
                continue
            else:
                log.error(
                    "Max retries exceeded due to timeout",
                    extra={"item_id": item_id, "max_retries": max_retries}
                )
                return ProcessResult(
                    status="TIMEOUT",
                    reason="max_retries_exceeded"
                )

        except Exception as e:
            # Unexpected error: log full traceback, fail safely
            log.exception(
                "Unexpected error",
                extra={"item_id": item_id}
            )
            return ProcessResult(
                status="UNEXPECTED_ERROR",
                reason="internal_error"
            )

    # Should not reach here
    return ProcessResult(status="UNKNOWN", reason="unreachable")
```

**Key Opus Patterns Shown:**

- ✅ Explicit timeout for every I/O operation
- ✅ Different handling for transient vs permanent errors
- ✅ Fallback strategies (cache, degraded mode)
- ✅ Rich logging with context (not just "failed")
- ✅ Assumptions documented in docstring
- ✅ Failure modes enumerated and handled
- ✅ Exponential backoff for retries

### If JavaScript/TypeScript (Promise-Based)

**Opus Pattern for Promise Chains:**

```typescript
// ✅ OPUS-STYLE TYPESCRIPT ERROR HANDLING

async function processOrderWithResilience(
  orderId: string,
  context: RequestContext,
): Promise<ProcessResult> {
  /**
   * ASSUMPTIONS:
   * - orderId is valid UUID (validated by caller)
   * - Payment service responds within 10s
   * - Inventory service responds within 5s
   * - Database is responsive (if not, timeout error caught)
   *
   * FAILURE MODES HANDLED:
   * 1. Order not found → return NOT_FOUND, don't retry
   * 2. Invalid order state → log error, don't proceed
   * 3. Payment timeout → retry 3x with backoff, then fallback
   * 4. Inventory unavailable → use optimistic reserve, reconcile later
   * 5. Database error → fail safe, alert team
   */

  const logger = context.logger.child({ orderId });

  try {
    // Step 1: Fetch order with timeout
    let order: Order;
    try {
      order = await Promise.race([
        database.orders.findById(orderId),
        sleep(5000).then(() =>
          Promise.reject(new TimeoutError("Database timeout")),
        ),
      ]);
    } catch (error) {
      if (error instanceof TimeoutError) {
        logger.error("Database timeout", { timeout_ms: 5000 });
        return {
          status: "TIMEOUT",
          reason: "db_timeout",
          orderId,
        };
      }
      throw error; // Unexpected error, let outer catch handle
    }

    if (!order) {
      logger.warn("Order not found", { reason: "missing" });
      return {
        status: "NOT_FOUND",
        reason: "order_missing",
        orderId,
      };
    }

    // Step 2: Validate order state
    const validStates = ["PENDING", "CONFIRMED"];
    if (!validStates.includes(order.state)) {
      logger.error("Invalid order state", {
        current_state: order.state,
        valid_states: validStates,
      });
      return {
        status: "INVALID_STATE",
        reason: `cannot_process_from_state_${order.state}`,
        orderId,
      };
    }

    // Step 3: Process payment with retry + fallback
    let paymentResult: PaymentResult;
    try {
      paymentResult = await retryWithBackoff(
        () => paymentService.charge(order.id, order.total),
        {
          maxRetries: 3,
          initialDelayMs: 100,
          backoffMultiplier: 2,
          shouldRetry: (error) => {
            // Only retry transient errors
            return (
              error instanceof NetworkError || error instanceof TimeoutError
            );
          },
        },
      );
    } catch (error) {
      if (error instanceof PaymentAuthError) {
        // Permanent error: customer auth failed
        logger.error("Payment authorization failed", {
          reason: "auth_failed",
        });
        return {
          status: "PAYMENT_FAILED",
          reason: "authorization_failed",
          orderId,
        };
      } else if (
        error instanceof TimeoutError ||
        error instanceof NetworkError
      ) {
        // Transient error after retries: use fallback
        logger.warn("Payment service unavailable, using async fallback", {
          error: error.message,
        });

        // Queue for async processing, mark order as PENDING_PAYMENT
        await queue.enqueue({
          type: "PAYMENT_RETRY",
          orderId,
          amount: order.total,
          maxRetries: 5,
        });

        return {
          status: "PENDING_PAYMENT",
          reason: "async_processing",
          orderId,
        };
      } else {
        // Unexpected error
        logger.error("Unexpected payment error", { error: error.message });
        throw error;
      }
    }

    // Step 4: Reserve inventory (optimistic)
    let inventoryReserved = false;
    try {
      await inventoryService.reserve(order.items, {
        timeout: 5000,
        onReservationFailed: async (failedItems) => {
          // Partial failure: log for manual review
          logger.warn("Partial inventory reservation failed", {
            reserved: order.items.length - failedItems.length,
            failed: failedItems,
          });
          // Don't fail the whole order; mark as PARTIALLY_RESERVED
          inventoryReserved = true; // Partial success is acceptable
        },
      });
      inventoryReserved = true;
    } catch (error) {
      if (error instanceof TimeoutError) {
        logger.warn("Inventory timeout, proceeding with optimistic reserve");
        // Optimistic: assume items available, reconcile in background
        inventoryReserved = true;
        await queue.enqueue({
          type: "INVENTORY_RECONCILIATION",
          orderId,
          items: order.items,
        });
      } else {
        logger.error("Inventory reservation failed", { error: error.message });
        // Failure: reverse payment
        await paymentService
          .refund(paymentResult.transactionId)
          .catch((refundError) =>
            logger.error("Refund failed", { error: refundError.message }),
          );

        return {
          status: "INVENTORY_UNAVAILABLE",
          reason: "cannot_reserve",
          orderId,
        };
      }
    }

    // Step 5: Persist order
    try {
      await database.orders.update(orderId, {
        state: "PROCESSING",
        paymentId: paymentResult.transactionId,
        reservedAt: new Date(),
      });
    } catch (error) {
      logger.error("Failed to persist order", { error: error.message });
      // Database error: this is critical
      // Try to reverse payment (best effort)
      await paymentService
        .refund(paymentResult.transactionId)
        .catch((refundError) =>
          logger.error("Refund after DB failure failed", {
            error: refundError.message,
          }),
        );

      // Alert team (this shouldn't happen)
      await alerting.critical("Order processing failed at persistence", {
        orderId,
      });

      return {
        status: "PERSISTENCE_ERROR",
        reason: "database_error",
        orderId,
      };
    }

    // Success path
    logger.info("Order processed successfully", {
      paymentId: paymentResult.transactionId,
      inventoryReserved,
    });

    return {
      status: "SUCCESS",
      reason: "processed",
      orderId,
      paymentId: paymentResult.transactionId,
    };
  } catch (error) {
    // Unexpected error fallback
    logger.error("Unexpected error in order processing", {
      error: error.message,
      stack: error.stack,
    });

    await alerting.critical("Order processing crashed", { orderId, error });

    return {
      status: "UNEXPECTED_ERROR",
      reason: "internal_error",
      orderId,
    };
  }
}

// Helper: Retry with exponential backoff (Opus-style)
async function retryWithBackoff<T>(
  fn: () => Promise<T>,
  options: {
    maxRetries: number;
    initialDelayMs: number;
    backoffMultiplier: number;
    shouldRetry: (error: Error) => boolean;
  },
): Promise<T> {
  let lastError: Error | undefined;
  let delay = options.initialDelayMs;

  for (let attempt = 0; attempt <= options.maxRetries; attempt++) {
    try {
      return await fn();
    } catch (error) {
      lastError = error as Error;

      if (attempt === options.maxRetries) {
        // Max retries exhausted
        throw error;
      }

      if (!options.shouldRetry(error as Error)) {
        // Don't retry this error type
        throw error;
      }

      // Sleep before retry
      await sleep(delay);
      delay *= options.backoffMultiplier;
    }
  }

  throw lastError || new Error("Retry loop failed");
}
```

**Key Opus Patterns:**

- ✅ Explicit timeout for every async operation
- ✅ Different handling for permanent vs transient errors
- ✅ Fallback strategies (async queue, optimistic)
- ✅ Partial success scenarios handled
- ✅ Cleanup/reversal on failure (refund)
- ✅ Rich logging with business context
- ✅ Assumptions and failure modes documented

use std::time::Duration;
use tokio::time::timeout;
use serde::{Deserialize, Serialize};

#[derive(Debug, Clone, Serialize, Deserialize)]
pub enum ProcessError {
    /// Database operation timed out (retryable)
    DatabaseTimeout { operation: String, timeout_ms: u64 },

    /// Item not found (permanent, don't retry)
    ItemNotFound { item_id: String },

    /// Invalid state transition (permanent)
    InvalidState { current: String, reason: String },

    /// External service error (transient, retryable)
    ExternalServiceError { service: String, reason: String },

    /// Unexpected internal error (don't retry)
    InternalError { reason: String },
}

impl std::fmt::Display for ProcessError {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        match self {
            ProcessError::DatabaseTimeout { operation, timeout_ms } => {
                write!(f, "Database timeout in {}: {}ms", operation, timeout_ms)
            }
            ProcessError::ItemNotFound { item_id } => {
                write!(f, "Item not found: {}", item_id)
            }
            ProcessError::InvalidState { current, reason } => {
                write!(f, "Invalid state transition from {}: {}", current, reason)
            }
            ProcessError::ExternalServiceError { service, reason } => {
                write!(f, "Service {} error: {}", service, reason)
            }
            ProcessError::InternalError { reason } => {
                write!(f, "Internal error: {}", reason)
            }
        }
    }
}

impl ProcessError {
    /// Determine if this error is retryable (transient)
    pub fn is_retryable(&self) -> bool {
        matches!(
            self,
            ProcessError::DatabaseTimeout { .. } |
            ProcessError::ExternalServiceError { .. }
        )
    }

/// Result type for process operations

/// Process status for API response
#[derive(Debug, Clone, Serialize, Deserialize)]

    pub reason: String,
    pub item_id: String,

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "SCREAMING_SNAKE_CASE")]

    NotFound,
    InvalidState,

/// OPUS-STYLE PROCESS FUNCTION
///
/// Assumptions:
/// - item_id is valid (caller validates)
/// - database responds within 5s (timeout enforced)
/// - external API responds within 10s (timeout enforced)
///
/// Failure modes handled:
/// 1. Item not found → permanent error, don't retry
/// 2. Invalid state → log error, don't process
/// 3. Database timeout → retry 3x with backoff
/// 4. API timeout → use cached result, log warning
/// 5. Unexpected error → log with full context, fail safe
pub async fn process_item_with_resilience(
    item_id: String,
    db: &Database,
    api: &ExternalApi,
    cache: &Cache,
    logger: &Logger,
) -> OperationResult {

    // Attempt with retry logic
    match retry_with_backoff(
        || process_item_impl(item_id.clone(), db, api, cache, logger),
        RetryConfig {
            max_attempts: 3,
            initial_delay: Duration::from_millis(100),
            backoff_multiplier: 2.0,
        },
    )
    .await
    {
        Ok(result) => {
            logger.info("Item processed successfully", &[
                ("item_id", item_id.clone()),
            ]);
            OperationResult {
                status: OperationStatus::Success,
                reason: "processed".to_string(),
                item_id,
            }
        }

        Err(ProcessError::ItemNotFound { .. }) => {
            logger.warn("Item not found", &[("item_id", item_id.clone())]);
            OperationResult {
                status: OperationStatus::NotFound,
                reason: "item_missing".to_string(),
                item_id,
            }
        }

        Err(ProcessError::InvalidState { current, reason }) => {
            logger.error("Invalid state", &[
                ("item_id", item_id.clone()),
                ("current_state", current),
                ("reason", reason),
            ]);
            OperationResult {
                status: OperationStatus::InvalidState,
                reason: "cannot_process_from_state".to_string(),
                item_id,
            }
        }

        Err(ProcessError::ExternalServiceError { service, reason }) => {
            logger.error("External service error", &[
                ("item_id", item_id.clone()),
                ("service", service),
                ("reason", reason),

                status: OperationStatus::TemporarilyUnavailable,
                reason: "service_unavailable".to_string(),
                item_id,
            }

        Err(ProcessError::DatabaseTimeout { .. })
        | Err(ProcessError::InternalError { .. }) => {
            logger.error("Internal error", &[("item_id", item_id.clone())]);
            OperationResult {
                status: OperationStatus::InternalError,
                reason: "internal_error".to_string(),
                item_id,
            }
        }

/// Implementation (separate from error handling)
async fn process_item_impl(
    item_id: String,
    db: &Database,
    api: &ExternalApi,
    cache: &Cache,
    logger: &Logger,
) -> ProcessResult<()> {

    // Fetch item with timeout
    let item = timeout(Duration::from_secs(5), db.fetch_item(&item_id))
        .await
        .map_err(|_| ProcessError::DatabaseTimeout {
            operation: "fetch_item".to_string(),
            timeout_ms: 5000,
        })?
        .map_err(|e| ProcessError::InternalError {
            reason: format!("Database error: {}", e),
        })?;

    let item = item.ok_or_else(|| ProcessError::ItemNotFound {
        item_id: item_id.clone(),
    })?;

    // Validate state
    const VALID_STATES: &[&str] = &["PENDING", "READY"];
    if !VALID_STATES.contains(&item.state.as_str()) {
        return Err(ProcessError::InvalidState {
            current: item.state,
            reason: "only PENDING and READY allowed".to_string(),
        });
    }

    // Enrich from API with fallback
    let enriched = timeout(Duration::from_secs(10), api.enrich(&item))
        .await
        .map_err(|_| {
            // Timeout: try cache
            logger.warn("API timeout, using cache", &[("item_id", item_id.clone())]);
            ProcessError::ExternalServiceError {
                service: "enrichment_api".to_string(),
                reason: "timeout".to_string(),
            }
        })
        .and_then(|api_result| {
            api_result.map_err(|e| ProcessError::ExternalServiceError {
                service: "enrichment_api".to_string(),
                reason: format!("API error: {}", e),
            })
        })?;

    // Persist (with error logging)
    timeout(Duration::from_secs(5), db.save_item(&item_id, &enriched))
        .await
        .map_err(|_| ProcessError::DatabaseTimeout {
            operation: "save_item".to_string(),
            timeout_ms: 5000,
        })?
        .map_err(|e| ProcessError::InternalError {
            reason: format!("Save failed: {}", e),
        })?;

    Ok(())
}

/// Generic retry logic (Opus-style)
pub struct RetryConfig {
    pub max_attempts: usize,
    pub initial_delay: Duration,
    pub backoff_multiplier: f64,
}

async fn retry_with_backoff<T, F, Fut>(
    mut f: F,
    config: RetryConfig,
) -> ProcessResult<T>
where
    F: FnMut() -> Fut,
    Fut: std::future::Future<Output = ProcessResult<T>>,
{
    let mut delay = config.initial_delay;
    let mut attempt = 0;

    loop {
        match f().await {
            Ok(result) => return Ok(result),
            Err(error) => {
                attempt += 1;

                // If not retryable or max attempts exceeded, fail
                if !error.is_retryable() || attempt >= config.max_attempts {
                    return Err(error);
                }

                // Sleep before retry (with jitter to avoid thundering herd)
                let jitter = Duration::from_millis(
                    rand::random::<u64>() % delay.as_millis() as u64
                );
                tokio::time::sleep(delay + jitter).await;
                delay = Duration::from_millis(
                    (delay.as_millis() as f64 * config.backoff_multiplier) as u64
                );
            }
        }
    }
}
